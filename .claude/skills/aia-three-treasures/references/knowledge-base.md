# 个人知识库（Obsidian）集成指南

本文件规定「友邦三宝」最终文稿**写到哪里、何时写、如何检测与暂停**。文件长什么样、怎么更新，见 [output-templates.md](output-templates.md)。

---

## 一、为什么要把三宝放进个人知识库

友邦三宝是代理人最核心的**个人资产**——它不是一次性稿子，而是要随经历成长、随场景复用、随业绩更新持续迭代的活文档。把它写进 Obsidian「第二大脑」：

- **可复用**：面谈、朋友圈、社群、增员等场景随时调取对应版本；
- **可链接**：与客户笔记、学习笔记、复盘笔记双向链接，形成个人知识网络；
- **可迭代**：版本递增、保留历史，能力升级后随时更新而不丢过去的自己；
- **属于你**：放在自己的 Vault 里，是你自己的资产，不依赖任何平台。

---

## 二、Vault 准备要求（使用前必做）

本 Skill 采用**强 Vault 模式**：必须在 Obsidian Vault 里运行，否则会暂停。

使用前请完成：

1. 在 Obsidian 中创建或打开一个 Vault（例如「我的第二大脑」）。
2. 在 Vault 根目录下确保存在 `00_个人背景/` 目录（与生财「第二大脑」内容创作系统结构一致）。

推荐的最小结构：

```
<你的 Vault>/
└── 00_个人背景/        ← 三宝文件写到这里
```

如果你已经在用生财那套「第二大脑」结构，`00_个人背景/` 已存在，无需改动。

3. 用 Claude Code 打开**这个 Vault 目录**（而不是别的文件夹），确保助手能读写其中的 Markdown。

---

## 三、启动检测规则

Skill 启动时，**先**执行以下检测，再开始任何访谈：

1. **判断当前工作目录是否为 Obsidian Vault**：检查当前目录下是否存在 `.obsidian/` 目录。存在则视为 Vault。
2. **确认 `00_个人背景/` 存在**：在当前工作目录下查找 `00_个人背景/`。
3. **不要在磁盘上广泛搜索其他目录**：只在当前工作目录判断，不去遍历磁盘找别的 Vault 或文件夹（防止把文件写到错误位置）。

---

## 四、缺失处理（暂停，不猜测）

检测到以下任一情况，**立即暂停**，不要继续访谈，也不要自作主张批量创建目录：

- **当前工作目录不是 Vault**（没有 `.obsidian/`）：
  - 告诉用户：「当前目录不是 Obsidian Vault。请在 Obsidian 中创建/打开一个 Vault，并确保含 `00_个人背景/` 目录，然后用 Claude Code 重新打开该 Vault。」
- **是 Vault 但缺少 `00_个人背景/`**：
  - 告诉用户：「检测到 Vault，但缺少 `00_个人背景/` 目录。请在 Vault 根目录下新建该文件夹后再继续。」
  - 可询问用户是否需要助手**代为创建这一个目录**；但**不要**自动批量创建其他目录。

暂停后等待用户确认已准备就绪，再重新检测并继续。

---

## 五、写入路径

四阶段全部确认后，写入：

```
<当前工作目录>/00_个人背景/友邦三宝_v1.md
```

- **首次生成**：`友邦三宝_v1.md`。
- **迭代**：文件已存在时先读取，按 [output-templates.md](output-templates.md) 的更新规则递增为 v1.1、v1.2……只更新对应章节，保留用户手动添加的无关内容，不盲目整文件覆盖。
- **重大重构**（重写某段、改变人设方向）：与用户确认后升 v2，旧版本归档副本放**同目录**（如 `00_个人背景/友邦三宝_v1归档.md`），避免覆盖历史。
- **复查**：写入后重新读取文件，检查路径、标题、关键字段、来源标记和待确认项，再向用户报告，不索要写入命令。
